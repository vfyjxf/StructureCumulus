# 24. 声明词汇：三个问题，三个答案

> 决策记录，2026-10-23。状态：**已定**；它触及的单元文件都已更新，代码迁移清单在 §9。它定下
> 一份声明该怎么描述：三个问题、三个类型。

## 1. 为什么会有“声明”这件事

两个玩家可以在同一块地上各建一台机器。方块只有一份，但两个控制器都认为那批方块是自己的：
掉落物出两份、能量算两次，拆掉其中一台，另一台还在对着一堆已经不存在的方块报告“结构成立”。

声明就是阻止这件事的记录。一行声明说：*这些格子属于这台实例*。所有行放在一起就是账本。
“这一格归哪台机器”必须永远只有一个答案，而答案就在账本里。

## 2. 为什么“检查”和“声明”必须分开

玩家从一块地旁边走过，宿主每个 tick 都在问：“这里能不能放一台机器？”这个问题绝不能写任何
东西：如果每次探测都声明一行，几秒钟内账本就会被几千条“也许”塞满，而且每一条都真的把地留给
问话的人。

所以这是两个性质不同的动作：**check** 只读并回答，**settle** 才写。这件事由 `23` 负责讲清楚。
本文件回答的是另一个问题：真要写的时候，**到底写了什么，两份声明怎么碰面**。

## 3. 旧词汇错在哪

模型是一个值一个值长出来的，每次都为了一台新机器，从来没有一起设计过：

| 需求 |
| --- |
| 熔炉外壳要占一整个盒子 |
| 管角只能占管子，不能占中间的空气 |
| 两格门必须正好绑满舱位 |
| 生物栏位什么都不想占 |

每加一个值，组合就翻一倍。于是合法性只能靠一张白名单：十二行，逐行检查。白名单本身就是
症状：**当一种非法组合需要被列出来再拒绝时，说明问题问错了。** 那十二行里有四行是胡说——
一份挡住所有其他人、却什么都不占的声明；另外五行合法但没有任何地方使用。

还有第二种损害：有一个值额外夹带了一件不相关的事——除了“不占格”，它还顺带允许读舱位盒子
外面。一个需要读门后一格的检查，只能靠放弃整个舱位的所有权来换取这个许可。这是个陷阱，
不是特性。

## 4. 三个问题

一个舱位需要回答三个问题。每个问题有自己的类型，每个类型只回答那一个问题。

### 问题一：检查必须建立什么？——`Coverage`

| 取值 | 含义 | 例子 |
| --- | --- | --- |
| `EVERY_CELL` | 舱位里的每一格都要被某个检查判定 | 熔炉墙：194 格，每格都必须是正确的方块 |
| `ONE_SUBJECT` | 检查绑定一个东西，而且它的占地正好等于舱位 | 两格门：上下两半，不多不少 |
| `ANY_SUBJECT` | 至少有一个东西在里面；不逐格判定 | 生物栏位：里面有头牛就够了 |

引擎需要它来判断检查集合**是否完整**。没有它，“194 格墙里只检查了 3 格”也会看起来像通过。

### 问题二：这台实例占哪些格子？——`Footprint`

| 取值 | 占哪些格 | 什么时候能算出来 |
| --- | --- | --- |
| `Box` | 舱位盒子，包含空气 | 构建蓝图时 |
| `Bound` | 检查绑定到的那些东西的非空气占地 | 匹配之后 |
| `Declared(cells)` | 作者写下来的一组格子 | 构建蓝图时 |
| `None` | 什么都不占 | 立即 |

“占”和“查”是两件事。管角是最清楚的例子：八格都必须正确，但只有四格是管子。把八格都占下来，
会让相邻的两个管角为它们共享的四格空气冲突，而它们其实从未接触。

`Box` 是用来保护空腔的：熔炉内腔占住 100 格空气，于是没人能把箱子塞进去。

### 问题三：这份声明和别人的声明怎么相处？——`Sharing`

| 取值 | 对同一格上另一份声明的影响 |
| --- | --- |
| `EXCLUSIVE` | 与任何其他主人冲突 |
| `SHARED` | 不与任何人冲突 |

两份声明相遇只有两种情形：其中一份排斥，或两份都不排斥。冲突规则只需要这一点，这也是这个
类型只有两个值的原因。

## 5. 规则

只有一种组合是真正的矛盾，所以组合层面只需要一条规则，外加三条原先藏在白名单里的不变量：

| 规则 | 时机 | 内容 | 码 |
| --- | --- | --- | --- |
| R1 | 构建 | `EXCLUSIVE` 的足迹不能是 `None` | `SC-CHK-0106` |
| R2 | 结算 | `EXCLUSIVE` + `Bound` 必须解析出至少一格 | `SC-BAY-0111`（新增） |
| R3 | 构建 + 结算 | `ONE_SUBJECT` 要求检查都是主体类，且绑定足迹**等于**舱位 | `SC-BAY-0107` |
| R4 | 构建 | `EVERY_CELL` 要求逐格检查覆盖整个舱位；`ANY_SUBJECT` 不允许逐格检查 | `SC-CHK-0106` |

其余组合全部允许，因为它们不是矛盾，而是一份说得通的意图。

R2 之所以存在，是因为绑定足迹可能算出来是空的：一扇没能绑上的门（两半没有同时读到），否则
会以“独占，却什么都不占”结算——那是 R1 的矛盾晚一步发生。

## 6. 模型必须仍然描述得出来的机器

| 机器 | 声明方式 |
| --- | --- |
| 熔炉外壳，194 格 | `EVERY_CELL` + `Box` + `EXCLUSIVE` |
| 熔炉内腔，100 格空气 | `EVERY_CELL` + `Box` + `EXCLUSIVE` |
| 两格门，原子 | `ONE_SUBJECT` + `Bound` + `EXCLUSIVE` |
| 管角，断言 8 格、占 4 格 | `EVERY_CELL` + `Bound` + `EXCLUSIVE` |
| 生物栏位，占动物的占地 | `ANY_SUBJECT` + `Bound` + `SHARED` |
| 只观测的舱位，什么都不占 | `EVERY_CELL` + `None` + `SHARED` |
| 声明一块地 | `ANY_SUBJECT` + `Declared` + `EXCLUSIVE` |
| 共享门框，谁都不占 | `ONE_SUBJECT` + `None` + `SHARED` |

生物栏位是旧词汇唯一表达不出来的情形：它的舱位要么什么都不占，要么占一块和动物无关的声明
盒子，中间没有第三种选择。

## 7. 得到什么，付出什么

得到的：

1. **矛盾写不出来。** 一条规则取代十二行白名单。
2. **一个词只管一件事。** `None` 不再夹带读许可；`Footprint` 不再把“现在能算”和“匹配后才能算”
   混在一起。
3. **补上一个真实缺口**：栏位可以占住动物的占地。
4. **名字自己会解释**：`EVERY_CELL` 不需要查术语表。

付出的代价：`Bay` 用 `footprint` + `sharing` 取代 `mode` + `scope`；文档 JSON 跟着变；大约
二十个测试和六份文档要改。没有兼容层——库还没发布，词汇只换这一次。

## 9. 迁移

代码，按顺序：

1. `Coverage`：值改名，`accepts` 拆成 R1/R4。
2. 一个密封的 `Footprint`（带 `resolve` 与“何时可知”）与一个 `Sharing` 枚举
   （`blocks()` 只对 `EXCLUSIVE` 为真）。
3. `Bay`/`BayBuilder`：组件与校验；`BlueprintBuilder` 的 B-7 只用 `EXCLUSIVE`。
4. `ClaimPlanner`：解析足迹，然后执行 R2。
5. `ClaimMatrix`：冲突谓词调用 `blocks()`；诊断消息写出共享取值。
6. `ClaimRow`：字段改名，排序键不变。
7. 测试：矩阵、账本、规划器、上面八台机器，以及 R1/R2 的拒绝路径。
