# Stage-2 re-check, role L — the options of every `RULE` item

Baseline `0ee39b9`, read-only except this file. Every claim below was re-read from the doc anchor
and the code anchor named by the report that raised it. Where a report's line number is off, the
number I found is given; the fact itself is marked `✓` or `✗`.

## 1. Method

- Read the nine slice reports' §2 tables and §3 "Rulings needed", plus
  `docs/design-notes/alignment-report.md` §3 (D-1…D-12), and collected the `RULE`-class items:
  the explicit ids (`RULE-1…RULE-4`, `RULE-D1…RULE-D3`, `RULE-H3…RULE-H5` as cited in
  `alignment-report.md` §4) and every §3 ruling item (A1/A3/A5, R-B1…R-B3, C-13…C-15, F2/F1/F6,
  G9…G12/G7, I-R1/I-R2, H-R1…H-R6, D-1…D-12).
- For each: re-read the quoted doc line and the quoted code line; then judged the options against
  (i) that evidence, (ii) the recorded decisions (`19` R27–R37, `24` §5/§9, `23` §7, `08` §4, I-10,
  I-16, R-01, `02` §2, `03` §3), (iii) the other units' statements, (iv) coherence between the
  options themselves.
- **Writability = spec-side.** The regeneration input is `docs/spec/`, so "leaves the code alone"
  is a *cost*, not a writability argument; I treat it as ripple. An option is *not* writable as
  written when it contradicts a recorded decision, a unit's own rule, or is self-defeating
  (e.g. it claims to restore a law it cannot).
- All code anchors are this repo's own sources (`src/kernel/java`), so native grep/read; no
  Minecraft/NeoForge fact was needed, so `sourcescout` was not bound.
