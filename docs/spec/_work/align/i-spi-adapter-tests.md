## 3. Rulings needed

**R1 — `create`'s second parameter: `Host` or the ledger?** (`15:28,114` vs `StructureKernel.java:57`)

- (a) **Keep `Host` only.** `create(Catalogs, Host)`; `Host.empty()` exists, so a document-less kernel is `create(catalogs, Host.empty())`. Cost: all 162 tests' `StructureKernel.create(Catalogs.empty(), ledger)` helper changes, and a ledger-only caller must name a record of three fields.
- (b) **Keep the ledger overload only.** Matches today's code and tests, but leaves `document`/`compile` with no port to their data, so `15` §4.4's `document` row and `02` §3's flow have no carrier.
- (c) **Both**, with `Host` canonical and `create(Catalogs, ClaimLedger)` a documented convenience that builds `Host.of(ledger)`.

*Recommendation: (c), stated in `15` §3 with the convenience spelled out*, because `P2`/`P4` want the ports in one immutable value while 162 existing tests show the ledger-only call is the common case; also promote `Host` to a glossary row (`15:449` asks for exactly that) and delete `catalogs()` from the facade or add it to the operation table — an accessor that returns the snapshot is not one of the nine.

**R2 — `derive`'s contract: who owns the store, and where does the derivation budget go?** (`15:70,230-233` vs `StructureKernel.java:82`)

- (a) **Spec's form.** `derive(Formed, List<DerivationSpec>, Budget)`, resolving `Deriver`s out of `catalogs.derivers()`; needs U6/U8's spec compiler and a `Budget` leg for derivation reads (`22` §9.5's two legs do not include one).
- (b) **Code's form.** `derive(Formed, ContextStore, List<Deriver<?>>)`: no catalog lookup, no budget, and the caller hands in the publish target — which contradicts `P2`/`P5` ("a kernel is a value") and `17:257` ("`StructureContext.at(instance)` reads published frames only").
- (c) **Middle.** `derive(Formed, List<DerivationSpec>, Budget)` with the store obtained from the instance the `Formed` names (an instance registry), and the budget charged as `22` §9.5's existing two legs.

*Recommendation: (c)*, with (b)'s `List<Deriver<?>>` kept only as an internal seam: the facade must not expose a mutable store, and `18` C-18 ("a deriver's reads are added to the result's `ReadSet`") cannot be written while the reads go into a store the caller could discard.
