## 3. Rulings needed

1. **RULE-D1 — the zero-arity combinator laws.** `07` §4.3's `anyOf` row says MISMATCH when "`m = a = u = t = 0`", which is satisfied by a zero-child array, so the spec's literal rule makes `anyOf()` a MISMATCH while `allOf()` is a MATCH ("`m = n`") — the code returns ABSTAIN for both (`Expectations.java:106`/`:72` fall out of their loops).
   - (a) Keep the literal counters: `anyOf()` = MISMATCH, `allOf()` = MATCH. Symmetric with logic, but an accidental empty vararg becomes a refutation.
   - (b) Refuse `n = 0` at construction (`IllegalArgumentException`), as `atLeast` already refuses `k > n`.
   - (c) Keep the code's ABSTAIN for both and add "`n ≥ 1`" to `07` §4.3, leaving `atLeast(0, …)` = MATCH as it is today.
   Recommendation: **(c)**, with (b) noted — an empty disjunction must not silently refute a bay, and `ABSTAIN` is already "I decline", which is what an empty test tree means.

2. **RULE-D2 — one enum or two (`DecisionKind` vs `Coverage`).** `07` §4.6 pairs focus kind and `Coverage` 1:1 and `Bay.validate` compares them (`blueprint/Bay.java:52-67`), yet both sides are the same triad today, written twice (`predicate/DecisionKind.java:5-7`, `blueprint/Coverage.java:5-7`).
   - (a) Two enums, both spelled `EVERY_CELL`/`ONE_SUBJECT`/`ANY_SUBJECT` (what `07` §3 + `01` §E say today): the focus *claims*, the bay *demands*, `SC-CHK-0106` compares them.
   - (b) One enum: delete `Coverage` and let `Bay` hold a `DecisionKind`; legality becomes a comparison of a value with itself.
   - (c) Keep `CUBIC`/`SUBJECT`/`PRESENCE` (code today) and rewrite `07` §3/§4.6 + `01` §E to match.
   Recommendation: **(a)** — the comparison in `Bay.validate` is meaningful only between two independently declared triads, and (b) would delete the only check that catches "a `PRESENCE` bay holding a cell-deciding focus"; (a) also resolves `24` §9.1's `Coverage` rename and `03` §1 in one step. The `block`-kind row of `07` §4.6 must go either way (D6): a no-arg `decisionKind()` cannot be bay-dependent.

3. **RULE-D3 — where a bay-wide expectation declares its reads.** `Expectation.reads()` takes no `bayCells` and is bay-independent, yet `Expectations.eachCell` walks the whole bay (`ctx.bay().points()`), and D9 already shows the value is never consumed.
   - (a) Give `Expectation` `ReadScope reads(Cuboid bayCells)`, mirroring `Focus` — honest closure, but every shipped test's signature changes and `ExpectationMeta`-based caching loses a bay-independent key.
   - (b) Keep `reads()` and have `MatchSession` charge the whole bay for any check whose subject is `BayView`.
   - (c) Keep today's rule and state in `07` §4.5 that a bay-wide expectation must be paired with a bay-reading focus (`Focuses.bay`/`allCells`), whose half of `Check.reads` then covers the cells; other pairings are `SC-CHK-0101` anyway.
   Recommendation: **(c)** plus the D9 fix (union both halves) — it needs no API change, and the subject-type pairing already forbids the dangerous combinations.
