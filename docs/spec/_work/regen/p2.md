# P2 — blind-generation probe: `kernel.claim` + `kernel.engine`

Method: `p2-skeleton.md` was written from `08`, `11`, `20`, `23` alone, then diffed against
`src/kernel/java/dev/vfyjxf/cumulus/kernel/{claim,engine}`. Direction of every mismatch was checked
against `19`'s R27 / R35 / R36 / R37 definitions; those four are excluded as known lag. Items whose
doc is newer and whose migration is scheduled elsewhere (`23` §9) are marked *lag* and kept out of
the findings.

Finding kinds: **(b)** doc states it differently from the code (a generator emits non-compiling code),
**(c)** doc never mentions it (a generator must invent it). **(a)** (doc states it, I missed it) is not
a finding and appears only in §4.

---

## 1. What I could not write from the docs alone

1. **Eleven engine-owned output types have no member list.** `11` §1 assigns the unit
   "detection output (`MatchOutcome`, `BayBinding`, `SeamBinding`, `Census`), the cheap pre-read
   (`PrescreenIndex`, `AnchorCandidate`, `Fingerprint`), incremental re-check (`ReadSet`, `ChangeSet`,
   `InvalidationIndex`, `InstanceRef`)" — that is the only sentence about any of them. Across all four
   files the sole members named are `BayBinding.subjects()` and `PrescreenIndex.of(view, plan, siting)`.
   Real: `MatchOutcome.java:18` `record MatchOutcome(Stage stage, Siting siting, WorldView view, Map<ContextKey<?>, Object> context, Bindings bindings, ReadScope reads)`,
   `BayBinding.java:10` `record BayBinding(NamespacedId bay, List<OccupantRef> subjects, Bindings bindings)`;
   `SeamBinding`, `Census`, `PrescreenIndex`, `AnchorCandidate`, `Fingerprint`, `ReadSet`,
   `InvalidationIndex`, `InstanceRef` exist nowhere in `src/`. Every one of the six invented shapes in
   my skeleton is wrong or unnecessary. **(c)**, and it is the single largest hole in the unit.

2. **`MatchSession`'s five members are a code comment, and its visibility is stated backwards.**
   `11` §3 ends with `// MatchSession: idempotent run(), spend(), remaining(), readSet(), probe(); writes are internal.`
   and §1 says "The session's mutators are package-private". Real (`MatchSession.java:59,99,103,122`):
   `public final class MatchSession`, a **public** constructor `MatchSession(MatchRequest request, @Nullable MatchSettler settler)`,
   a package-private `MatchSession(MatchRequest, @Nullable MatchSettler, ContextStore)`, and `run()` only —
   no `spend()`, `remaining()`, `readSet()`, `probe()`. `Spend` lives on `InstanceBudget`; `ReadSet` does
   not exist. Return types for `remaining()`/`probe()` are unknowable. **(b)+(c)**.

3. **`Sharing` is `ClaimMode`, with a third value no doc mentions.** `08` §3:
   `public enum Sharing { EXCLUSIVE, SHARED; public boolean blocks() { … } }`; §2 fixes the two values.
   Real `ClaimMode.java:3-8`: `EXCLUSIVE, SHARED, RESERVED` and `public boolean excludes()`.
   `grep -rn "ClaimMode\|RESERVED"` over `docs/spec` (excluding `_work`) returns **zero** hits — the
   vocabulary the code uses, and the meaning of `RESERVED` (`08` §4.2 says "there is no strength order"
   and the matrix is total over two values; a third makes the §4.2 table undefined). **(b)+(c)**.

4. **`Footprint` is `ClaimScope`, with all four arms renamed — and `08` §1 denies owning it.**
   `08` §3 line 42: `public sealed interface Footprint permits Box, Bound, Declared, None` with
   `Box` = "the bay cuboid, air included", `Bound` = "union of bound non-air footprints", `None` = "no cell".
   Real `ClaimScope.java:7-25`: `permits Owned, Occupied, Declared, Audit` (`Audit` = reads anywhere).
   Meanwhile `08` §1 lines 10-11: "**Does not own** the bay's `Coverage`, `Footprint` and `Sharing`
   declaration (U5)". So the doc says (i) claim owns these types, (ii) claim does not own them, and
   (iii) the names — which are the ones in the code's call sites (`Bay.scope()`, `Bay.mode()`) — appear
   in neither statement. `ClaimPlanner.java:58,101-118` branches on `ClaimScope.Owned/Occupied/Declared/Audit`,
   not on `Footprint.Box/Bound/None`. **(b)+(c)**.

5. **`UndecidedReason`'s value set is disjoint from the doc's.** `11` §4.4 fixes
   "`CANCELLED > DIRTY_UNSTABLE > BUDGET_EXHAUSTED > LEDGER_MOVED > LEDGER_UNAVAILABLE > UNREADABLE > ABSTAINED > NO_STEPS`"
   and §4.1 uses `NO_JUDGING_UNIT` as a reason. Real `UndecidedReason.java:4-11`:
   `BUDGET_EXHAUSTED, DIRTY_UNSTABLE, LEDGER_MOVED, SUBJECT_ABSENT, LEASE_CLOSED, WORKER_FAILED, DESIGN_DEFECT`.
   Four doc values (`CANCELLED`, `LEDGER_UNAVAILABLE`, `UNREADABLE`, `ABSTAINED`, `NO_STEPS`) have no
   constant; three code values have no doc sentence. The doc's `NO_JUDGING_UNIT` is not a reason in the
   code at all — it is `FindingCode ENG,201` (`MatchSession.java:66`) passed as `UndecidedReason.DESIGN_DEFECT`
   (`MatchSession.java:152`). Neither set contains the other, so a generator cannot even pick a
   defensible subset: the precedence ladder in §4.4 is unwritable. **(b)+(c)**.

6. **Two different `Overlap` types, and `ClaimMatrix`'s real public surface is 3× what the doc lists.**
   `08` §3: `record Overlap(NamespacedId low, NamespacedId high) implements Comparable<Overlap>`,
   nested inside `ClaimPlan`. There is no `ClaimPlan.Overlap` in the tree; `ClaimMatrix.java:158` declares
   `public static final class Overlap` with `challenger()`, `incumbent()`, `cells()` and no `Comparable`.
   `ClaimMatrix` also carries eight members and two constants the doc never lists —
   `OVERLAP_CODE`/`CONFLICT_CODE` (`:25-26`), `internalOverlaps` (`:60`), `conflictsWith`, `rowsOf`,
   `overlapFindings`, `overlapFinding`, `conflictFinding` ×2 — and `08` §3 presents the class as one
   static predicate. The semantics diverge too: `08` §4.2 says a same-blueprint overlap "is `SC-BPT-0002`,
   never a ledger conflict, because `ClaimMatrix.conflicts` is false for two rows of one `(owner, siting)`",
   while `internalOverlaps` emits `OVERLAP_CODE = CLM,1` and `InMemoryClaimLedger.java:47-52` returns it as a
   `ClaimConflict` before the CAS. **(b)**.

7. **`ClaimPlanner.Derived` is named with three components and defined by none of them.**
   `08` §3 line 93-95: `public record Derived(List<ClaimRow> rows, List<ClaimPlan.Overlap> overlaps, CuboidSet staticFootprint)`,
   and `11` §4.1 step 9 reads the ledger over `d.staticFootprint()`. Nothing in `08`, `11`, `20` or `23`
   says what `staticFootprint` contains (the union of derived row cells? every non-`None` bay's `cells`?
   the DESIGN-time static half?), who fills `overlaps` when the plan is already `Matched`, or why a
   settled plan needs both rows and overlaps. Real: no `Derived` type; `ClaimPlanner.plan(...)` (`:45`)
   returns `ClaimPlan` and produces no read box, so `MatchSession` never calls `ledger.read` — the whole
   §4.5 "check reads the ledger" step has no code path. **(c)**.

8. **`ClaimView` is declared an interface, is a record; `ClaimConflict.findings` is a bundle, not a list.**
   `08` §3: `public interface ClaimView { List<ClaimRow> rows(); long revision(); boolean available(); }`
   and `record ClaimConflict(List<ClaimRow> rows, List<Finding> findings)`. Real
   `ClaimView.java:9`: `public record ClaimView(List<ClaimRow> rows, long revision, boolean available)`
   plus `unavailable()` and `rowsIn(Cuboid)`; `ClaimVerdict.java:21`:
   `record ClaimConflict(List<ClaimRow> rows, FindingBundle findings)`. A doc-following generator writes
   `new ClaimView(...)` (cannot: interface) and `conflict.findings()` typed `List<Finding>` (cannot:
   `FindingBundle`). Same for `MatchResult`: `11` §3 declares `FindingBundle findings();` on the root,
   real `MatchResult.java:24` is `FindingBundle bundle();`. **(b)**.

9. **`Formed.readSet()` is specified in terms of a member nothing declares.**
   `11` §3: `public ReadSet readSet(); // union of outcome.stepReads()`. `MatchOutcome` has no
   `stepReads()` — it has `ReadScope reads`; `ReadSet` has no type; and `Formed` has no `readSet()`
   (`MatchResult.java:52-80`). `20` §5.2 and `11` §4.6 talk about `ReadSet.cells` / `ReadSet.occupants`
   as durable vs snapshot-scoped, which is a third shape. Three incompatible descriptions of one value. **(b)+(c)**.

10. **`RetryToken.of(long expected, long actual)` does not exist; the token carries no numbers.**
    `08` §5 line ~305: `RetryToken.of(m.expected(), m.actual())` with the inline comment
    `// RetryToken.of(long expected, long actual)`, and `08` §4.5 says a second move is
    "`Undecided(LEDGER_MOVED)` with a retry token". Real `RetryToken.java:7`:
    `public record RetryToken(Ticket ticket, Stage stage)`; `of(Ticket, Stage)`, `next()`. A generator
    writes the doc's factory and cannot compile; it also cannot know that a token is derived from a
    scheduler ticket (`MatchRequest.retryToken()` at `MatchRequest.java:44`), which no doc states. **(b)+(c)**.

11. **"`InstanceRecord` is the only owner of the capture" — the real class owns no capture.**
    `20` §1.8 and §4.3: "The instance owns its capture. `InstanceRecord` is the only owner … `Admitted`
    and `Formed` hold child handles"; `11` §4.6: "`InstanceRef.generation` is *instance* generation,
    derived from `contextRevision` plus the settled match, never bumped by hand". Real
    `InstanceRecord.java:13-70`: fields `id`, `generation`, `previous`, **no lease**, plus
    `nextGeneration()` (`:43`) and `remember(Formed)`; `MatchSettler` calls `record.nextGeneration()`
    (`MatchSettler.java:97`), i.e. bumped by hand. No `InstanceRef` type exists; the id type is
    `InstanceId`. The ownership invariant of `20` §1.8 is unrepresentable in the code as written. **(b)**.

12. **`DirtyIndex`'s eight-member shape, and `WatchState` / `WatchedInstance`, do not exist.**
    `20` §5.2 prints `watch(WatchedInstance)`, `unwatch(InstanceRef)`, `instancesIn(SectionKey)`,
    `instancesFor(EntityWindow)`, `markSection(SectionKey, DirtyCause)`, `markPayload(LatticePoint, DirtyCause)`,
    `markEntityFootprint(Cuboid, Cuboid)`, `contentStamp(SectionKey)`, plus `enum WatchState { CLEAN, DIRTY, CHECKING, BROKEN, UNKNOWN }`
    and `final class WatchedInstance { snapshot(); state(); dirtyEpoch(); dirtyForCheck(); checkInFlight(); cellStamp(unit); sections(); revOf(int); payloadRev(p); entityRev(uuid); stale(int); … }`.
    Real `DirtyIndex.java:22-127` is a dimension-keyed mark table: `stamp()`, `markCell(LatticeKey)`,
    `markCell(LatticePoint)`, `markSection(SectionKey)`, `markEntity(EntityKey, Cuboid)`,
    `cellStamp(ReadScope)`. No `watch`/`unwatch`, no instance index, no `contentStamp`; neither
    `WatchState` nor `WatchedInstance` exists in `src/`. **(b)** — 20 §5.2 reads as an API spec, and
    none of it is the API.

13. **`ChangeSet`'s only constructor example is the wrong arity, and its named field is absent.**
    `11` §5: `new ChangeSet(Set.of(LatticeKey.of(LatticePoint.of(12, 65, 10))), Set.of(), 41L)` — three
    arguments; §4.6: "a `ChangeSet` with no changed cell but non-empty `changedTypes` is *unlocalised*".
    Real `occupant/ChangeSet.java:18`: `record ChangeSet(Set<LatticeKey> cells, Set<SectionKey> sections, Set<LatticeKey> payloads, Set<EntityKey> entities, Set<NamespacedId> keys, long revision)`
    — six components, and no `changedTypes` (the nearest name is `keys`, whose meaning is unstated).
    `11` §1 also lists `ChangeSet` as engine-owned; the file is in `kernel.occupant`. **(b)+(c)**.

14. **`MatchSettler`: a whole kernel class the docs never name, and it holds an `Executor`.**
    `11` §1's ownership list has no settle collaborator; `20` §1.2 states "The kernel receives no
    executor, future or callback"; `11` §4.8: "No live world, ledger write, `ThreadLocal`, I/O, clock or
    randomness enters the kernel". Real `MatchSettler.java:28-150`: `private final Executor executor`
    (`:34`), factories `inline(ledger)` / `on(ledger, executor)`, and every ledger call wrapped in
    `new FutureTask<>(…)` + `executor.execute(…)` + `future.get()` (`:114-133`). A generator following
    `11`/`20` would have no reason to create this class at all, and if it did, would not give it a
    thread pool inside the kernel. **(b)**.

15. **`InstanceBudget`'s four declared members vs the real five, and `Budget` is unmentioned.**
    `11` §4.6: `long discards(NamespacedId unit); long attempts(NamespacedId unit); Spend spent(); boolean tryCharge(int cells, int sections);`.
    Real `InstanceBudget.java:9-54`: `of(Budget)`, `unbounded()`, `limit()`, `spend()` (not `spent()`),
    `tryCharge(int,int)`, `tryCharge(Spend)`, `remaining()`; no per-unit counters at all. The ceiling
    type `Budget` (`record Budget(int cells, int sections)`, `Budget.java`) is named in no spec file, so
    a generator cannot know whether `InstanceBudget` holds a limit or is one. **(b)+(c)**.

because a generator hits them before it ever reaches the code:

- `ClaimRow implements Comparable<ClaimRow>`, `ClaimRow.ordered(List)`.

**engine**

## 4. What the docs do cover well

These I wrote from the doc alone and the real type matched member-for-member; they are the parts a
generator would have got right:

- **`CaptureGate`** — `20` §5.4 + `11` §4.6 give all three verdicts and both facts, in the right order
  (`isValid()` first, then `changeCount()`); `CaptureGate.java:29-34` is exactly that, nested `enum Verdict`
  included. This is the best-specified type in either package.
- **`DropCause`** — both constants and their meanings, verbatim (`11` §4.6).
- **`CacheMode`** — `OFF | PARTIALS | OUTCOMES`, and the one-line semantics of each (`11` §4.7, `20` §6.3).
- **`MatchPolicy`** — three components, `defaults()` = `(8, OUTCOMES, false)`, "a host may only narrow"
  (`11` §3, §4.7). Only `of(...)` and the constant are extra.
- **`MatchResult`'s six arms' component lists** — `11` §3 reproduces them exactly, including which two
  arms carry a lease and that `close()` releases only that child handle; `MatchResult.java` matches on
  `Admitted`, `Formed`, `Undecided`, `Deferred` (the R27 fields aside).
- **`SettleRequest`'s remaining four components and the CAS shape** (`08` §2/§3, `23` §3.1) — the world
  component aside (R35).
- **`ClaimVerdict`** — three arms, three component lists (`Settled(revision, rows)`,
  `ClaimConflict(rows, findings)`, `RevisionMoved(expected, actual)`); only the bundle-vs-list type differs.
- **`ClaimRow`'s claimant identity** — `(owner, siting, bay)` on the row and the settlement key read off
  the rows themselves (`08` §4.1) is right in the code, and the doc's insistence that siting is a row
  component pays off (`SettleRequest`'s guard).
- **`ClaimMatrix.conflicts`' truth table** — including the "false for two rows of one `(owner, siting)`"
  exclusion, which `ClaimMatrix.java:35-45` implements exactly as `08` §4.2 words it.
- **Conflict findings' text and labels** — `08` §4.6's message template, the `(owner, bay)` grouping,
  PRIMARY = challenger / SECONDARY = incumbent on the contested cell: `ClaimMatrix.java:141-157` is a
  literal transcription, down to the punctuation.
- **`SnapshotLease`** — all six members and their meanings, including `retain(PinBudget) → Outcome` with
  `Missing(SC-MC-0502)` (`20` §4.1); the interface matches member-for-member.
- **`Spend(cells, sections)`** and the two billing legs with their charge rules (`11` §4.1, `20` §7).
- **`ClaimSet`'s canonical order + `List.copyOf`** — `08` §3's compact constructor is exactly the code's
  first line (the code adds `ordered(...)` and two members).
- **`AnchorSpec` / `AnchorResolver`** — `11` §4.2 prints both verbatim, and `AnchorSpec` exists at the
  path the doc implies. `AnchorResolver` does not exist yet, but its single method is fully specified,
  which is the difference between a gap and a build task.
